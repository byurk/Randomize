# Randomize — Jamovi Module for Randomization-Based Inference

## Project overview
A Jamovi module and R package for teaching randomization-based inference in introductory statistics. Provides permutation tests and bootstrap CIs for means, proportions, slopes, and contingency tables.

- **Repo**: https://github.com/byurk/Randomize
- **Package name**: Randomize
- **Author**: Brian Yurk (yurk@hope.edu)

## Branches
- `main` — production code used by students
- `refactor` — major refactoring (PR #2 open, pending manual Jamovi GUI testing before merge)

## Key directories
- `R/*.b.R` — analysis backend implementations (one per analysis)
- `R/*.h.R` — auto-generated by jmvtools from YAML (do NOT edit directly)
- `R/*_utils.R` — shared utility functions (bootstrap, permutation, contingency table, descriptive plot)
- `R/convenience.R` — plot(), results_table(), desc_table() for R/Quarto usage
- `jamovi/*.yaml` — Jamovi UI definitions (.a.yaml = options, .r.yaml = results, .u.yaml = unit specs)
- `tests/test_analyses.R` — 20 tests covering all 13 resampling analyses

## Build & test
```bash
Rscript -e "library(jmvtools); install()"    # build + install into Jamovi
Rscript -e "devtools::load_all('.')"         # load for R development
Rscript tests/test_analyses.R                # run automated tests
```

## Architecture
Each analysis is an R6 class (e.g. `twomeanhtestClass`) inheriting from a jmvcore-generated base. The `.run()` method orchestrates computation, table population, and plot state setup. Plot rendering callbacks (`.permPlot()`, `.bootPlot()`, `.descplot()`, `.linplot()`) are called by the Jamovi framework.

Shared logic lives in utility files:
- `bootstrap_utils.R` — CI computation + bootstrap distribution plotting
- `perm_utils.R` — p-value computation + null distribution plotting + seed/direction helpers
- `conttab_utils.R` — contingency table data prep and display
- `descplot_utils.R` — grouped mean/median descriptive plots
- `convenience.R` — user-facing helpers for extracting plots/tables from R

## Build notes
- Rscript is at `/usr/local/bin/Rscript` (not on PATH in some shells).
- Jamovi is at `/Applications/jamovi.app`. Its bundled R is at `.../Frameworks/R.framework/Versions/4.4-arm64/Resources/bin/Rscript`.
- Installed module lives at `~/Library/Application Support/jamovi/modules/Randomize/`.
- **IMPORTANT**: `.omv` files cache old module code. When testing changes, always open Jamovi fresh with no `.omv` — import data from scratch. Otherwise the old code rides along with the file.
- The `jmvtools::install()` architecture mismatch warning (arm64 vs x86_64) is harmless; the install succeeds.

## Important notes
- The .h.R files are regenerated by `jmvtools::install()`. Edits to them will be overwritten.
- The `dplyr::select` vs `jmvcore::select` import warning is benign (we use explicit `dplyr::select()`).
- All analyses use the `infer` package for bootstrap/permutation resampling.

## Known issues
- **Contingency table plot fails for certain large datasets (pre-existing)**: With `yrbss.csv` using strength_ind vs sleep_ind (N=12,219, 3x3 table, X²=121.3), the null distribution plot never renders (spins) even though `.init()`, `.run()`, `.preparePlot()`, and `.permPlot()` all complete successfully. Debug logging confirmed the plot is built, printed, and returned without error, but Jamovi's rendering pipeline does not display it. Even a hardcoded trivial test plot (5 points scatter) fails for this variable combination. Other 3x3 tables work (e.g., helmet_ind vs text_ind with N=5,395). This is a **pre-existing Jamovi framework bug** — not caused by the refactor.
